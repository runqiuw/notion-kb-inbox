# 各来源怎么采集

所有来源的共同规则：**拿不到实质正文就不建页**，放进 Firestore `staged` 暂存区，记下失败原因，
`/retry` 和每日自动重试会按首次入库的完整流程再跑一遍。

## 普通网页

1. 先用 trafilatura 抽正文。
2. 失败再交给 [parsehub](https://github.com/z-mio/ParseHub)（覆盖约 20 个平台）。
   知乎、小红书这类对纯 HTTP 返回 403 的直接跳过第一层。
3. 确认是 JavaScript 空壳或加载占位页时，再用 Playwright / Chromium 渲染一次。

动态渲染的限制（单实例 1 CPU / 1 GiB）：每实例最多一个浏览器，渲染最多 35 秒；不下载图片、
媒体和字体；所有请求只连到已校验的公开 IP，拦截内网 / 云元数据地址、WebSocket、Service Worker；
不复用任何登录状态。只有标题或「Loading…」不算正文。

关闭渲染兜底：`DYNAMIC_WEB_ENABLED=0`。

会员登录提示页（例如只返回「请登录 / cookie 说明」的页面）即使 HTTP 200 也会暂存。
不设正文最短长度，不会因为文章提到这些词就拒绝。

## 论文

- arXiv、DOI 链接走官方 API（arXiv API、Crossref、Semantic Scholar），只保留标题、作者、时间、abstract。
- **论文项目页**（如 `xxx.github.io`）：有明确的论文链接，且有 abstract 或自身 BibTeX，并核对上官方论文标题后，
  按论文入库：保留项目页的中文总结，再补完整摘要原文和译文。引用了别人论文的博客不会被当成论文。
- 链接指向 CVF 的论文从 CVF 官方页取摘要和会议名。
- `S2_API_KEY` 可选（免费申请）。不填时 Semantic Scholar 匿名池限流很紧，「会议/期刊」「引用数」常为空。
- `CROSSREF_MAILTO` 可选，填了进 Crossref 更快的池子。

## 小红书

- 正文 + 图片，图片交给多模态模型逐张判断有没有实质信息、写逐图总结、保留可辨认的文字转写。
- 专用 OCR 对任何图都会吐字，封面卡和水印会污染存档，所以不用。装饰图写明跳过理由。
- 视频笔记只保存发布者简介，见 [video.md](video.md)。
- 评论不采集。

## 多图帖子（分批读图）

超过 4 张图，或图片编码后请求超过 3 MiB 的帖子走分批路径：

- 每批最多 4 张，再按请求大小拆分；单张原件上限 5 MiB。
- 每张原件和每个成功批次立即归档到 GCS，进度存在 Firestore `image_jobs`。
- 任务时间不够会派发 `/tasks/images` 续跑，只补未完成部分；连续 3 次没有进展就暂停自动重试，等 `/retry`。
- 全部图片读完、汇总完成后才写入资料页并标「完成」。

1–4 张的帖子走单次调用。**模型必须支持视觉**，否则会报 `is not a multimodal model`。

## 知乎

1. 先用专用解析器（parsehub）。`ZHIHU_DC0` 是访客设备标识（不是登录态，不要放 `z_c0`），可选。
2. 失败后用 [Jina Reader](https://jina.ai/reader/) 免费匿名接口读单篇文章 / 回答，无需 API Key。
   原始返回归档后才入库。`JINA_READER_ENABLED=0` 关闭。**注意内容会经过 Jina 这个第三方。**
3. 都失败就暂存。知乎经常对数据中心 IP 返回「请登录」（错误码 40353），配置 `ZHIHU_DC0` 也不保证能恢复。

**评论精华**：只采集回答 / 文章的评论（问题页不展开）。高赞排序最多 3 页，另抽样高赞评论的回复，
最多保留 100 条；模型选出精华和「评论中的纠错与争议」，每条必须对应真实评论 ID。
评论观点与正文、你的想法分开展示，高赞不等于事实正确。采集失败时正文照常入库，页面写明未采集。

## 微信公众号

**服务器抓不到。** 微信按出口 IP 拦截数据中心，换服务器、换第三方阅读器（包括 Jina）都一样，
返回「环境异常，完成验证后即可继续访问」。`extract.fetch_wechat()` 会明确报这个原因。

替代做法：把文章截图发给 bot，走图片识别。多张截图会合成一页。

## 图片、PDF、文件

- **单张图片**：Cloud Vision OCR + 概览，原图归档。
- **相册**：Telegram 把相册拆成多条消息且不说哪条是最后一条。第一条用 Firestore `media_groups`
  的 `create` 抢占整组，延迟 6 秒入队等其他图到齐；超过 21 秒才到的图单独成页。旧路径最多处理前 9 张。
- **PDF**（含扫描件）：中文概览与要点 + 原件归档，不把提取的全文写进 Notion。
- **文本文件**（.txt、.md）：整份存成「其他」。
- Telegram Bot API 下载上限 20 MB。
- **语音、视频、音频、贴纸**：明确回复「没有存下来」，不会静默消失。
