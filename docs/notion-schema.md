# Notion 数据结构

**代码按中文属性名和选项名写入。** 改一个字段名，写入就会 400。重建时必须逐字照抄，
或直接用 `tools/setup_notion.py` 建库（见 [setup-notion.md](setup-notion.md)）。

两个数据库放在同一个根页面下（默认叫「科研阅读与思考」，名字随意，bot 只按 database id 访问）：

- **资料库**：外部材料，一条材料 = 一个页面。
- **想法与笔记**：你自己的想法，可以关联资料，也可以独立存在。

可选的 Wiki 层（「Wiki 条目」「维护记录」）不由 bot 写入，字段见 [wiki-layer.md](wiki-layer.md)。

## 资料库

| 属性 | 类型 | 选项 / 说明 | 谁写 |
|---|---|---|---|
| 标题 | title | 来源原标题，不翻译；有原始链接时末尾加可点击的 `↗︎` | bot |
| 材料类型 | select | 帖子 / 网页 / 论文 / 视频 / 播客 / 聊天记录 / 图片 / 其他 | bot |
| 来源平台 | select | 小红书 / 知乎 / B站 / YouTube / 微信 / 网页 / 论文 / 本次对话 / 演示 | bot |
| 阅读状态 | select | 待读 / 阅读中 / 已读 / 搁置 | **只有人改** |
| 处理状态 | select | 完成 / 需处理（正文已存、整理失败）/ 等待采集（`/retry` 会按它筛选，**必须存在**） | bot |
| 主题 | multi_select | 标签，最多 3 个，可为空；词表见 [tags.md](tags.md) | bot 初次建议，之后人改；重跑保留 |
| 卡片摘要 | rich_text | 中文概览首句，最长 90 字，给画廊卡片用 | bot 建页写入，重跑只补空值 |
| 原始链接 | url | | bot |
| 作者 | rich_text | 仅论文，最多 12 位 | bot |
| 发表时间 | date | 仅论文 | bot |
| 会议/期刊 | rich_text | 仅论文，常为空（preprint 没有会议，Semantic Scholar 会限流） | bot |
| 引用数 | number | 仅论文，常为空 | bot |
| 关联笔记 | relation → 想法与笔记 | 双向，由笔记侧的「关联资料」自动生成 | Notion |
| 收集时间 | created_time | 只读 | Notion |
| 缩略图 | files | 画廊卡片预览图：内容首图 / 论文插图 / 按类别的占位图 | bot |
| 样例来源 | select | 用户提供 / 公开材料演示 / 合成演示 | bot 一律写「用户提供」 |
| 记录编号 | unique_id | 可选，前缀 `SRC` | Notion |
| 卡片信息 | formula | 可选，把材料类型与阅读状态合成一行显示在卡片上 | Notion |

**阅读状态和处理状态必须独立。** 处理状态说机器干完没有，阅读状态说你读了没有。
「AI 整理完成」不等于「你读过」。

## 想法与笔记

| 属性 | 类型 | 选项 / 说明 | 谁写 |
|---|---|---|---|
| 标题 | title | 取正文前 60 字 | bot |
| 类型 | select | 随想 / 阅读笔记 / 研究分析 / 聊天提炼 | bot（有关联资料写「阅读笔记」，否则「随想」；分享会话写「聊天提炼」） |
| 笔记状态 | select | 待展开 / 整理中 / 已形成结论 | **只有人改** |
| 主题 | multi_select | 同资料库；有关联时继承资料的标签 | bot / 人 |
| 关联资料 | relation → 资料库 | 双向 | bot |
| 资料标签 | rollup | 关联资料 → 主题，show_unique；方便自己决定打什么标签 | Notion |
| 创建时间 | created_time | 只读 | Notion |
| 样例来源 | select | 同资料库，另有「流程测试」 | bot |

新增 select 选项不用改代码，Notion 允许写入时创建新选项。**删除或改名已有选项会让写入失败。**

## 建议的视图与首页

API 建不了视图，需要在 Notion 里手工建。以下是参考布局，可按喜好改：

| 视图 | 类型 | 筛选 | 排序 |
|---|---|---|---|
| 全部资料 | table | 无 | 收集时间 ↓ |
| 待读 | gallery 或 list | 阅读状态为待读或阅读中 | 收集时间 ↓ |
| 已读 | list | 阅读状态 = 已读 | 收集时间 ↓ |
| 待处理 | table | 处理状态 ≠ 完成 | 收集时间 ↓ |
| 最近想法 | list（笔记库） | 类型 ≠ 聊天提炼 | 创建时间 ↓ |
| 聊天提炼 | list（笔记库） | 类型 = 聊天提炼 | 创建时间 ↓ |

画廊卡片：预览选「缩略图」，图片适应选 contain，显示标题、卡片摘要、卡片信息、主题。

首页参考：顶部一个 callout，放「记个想法」链接（`https://t.me/<你的bot用户名>`）和常用标签页链接；
主区是待读画廊；下方左右两栏放「最近想法」和「聊天提炼」。

注意两个 Notion 限制：

- 「待处理」用「不等于完成」筛选，**处理状态为空的行也会出现**。
- 视图**不能按 rollup 筛选**：`资料标签 contains ...` 会被静默丢弃成空条件，匹配全部。按标签筛笔记只能用「主题」。

## 「记下想法」入口

两条路径都落在想法与笔记库：

1. **材料页末尾的 ✍️ callout**：链接是 `https://t.me/<bot>?start=n<32位页面id>`，
   点进 Telegram 后下一条文字消息就记为这份材料的笔记（Firestore `pending/{chat_id}`，一小时过期，
   可点取消）。走 bot 的建笔记流程，**标签会继承**。取不到 bot 用户名时不写这个块。
2. **资料库的 Button 属性「记下想法」**（可选，只能手工建）：一键在笔记库建页并关联当前资料。
   按钮读不到源页面的多选值，**标签不继承**。

## 页面内容约定

材料页按固定顺序拼块，**只在有内容时才出现对应小节**。

网页、博客、公众号、图文帖：

```
原标题 ↗︎              ← 只有箭头是外链
## 中文概览
## 中文要点
## 逐图总结             ← 有信息的图逐张 1–3 句；每张下面折叠 OCR 原文
▸ 跳过了 N 张装饰性图片
▸ 原始正文（展开查看） ← 长正文拆成多个折叠块
▸ 来源与定位           ← 链接、时间、GCS 归档位置
## 我的想法
✍️ 读完想说点什么？→ 记下想法
   ─── 每条关联笔记一个同步块引用
```

论文（arXiv / DOI / 论文项目页）：

```
原标题 ↗︎
## 中文概览            ← 基于 abstract
## Abstract · 中英对照  ← 原文完整保留 + 中文译文
▸ 来源与定位           ← arXiv id、DOI、时间、引用数
## 我的想法
```

论文不抓 arxiv.org 的 HTML，走官方 API（`export.arxiv.org/api/query`）。抓 HTML 会把
arXivLabs 等页面家具当成正文。三个来源都没有摘要就不建页，进暂存区。

视频、聊天分享的页面结构见 [video.md](video.md)、[chat-shares.md](chat-shares.md)。

三条不能破的规则：

1. **机器内容、原始材料、你的想法分区展示。**
2. **自动化只写自己建的块。** 重跑只追加，不原地改写人工正文。唯一例外是你编辑了 Telegram 原消息。
   属性不同：重跑保留标签、阅读状态、卡片摘要，但**会覆写标题、材料类型、处理状态**。
3. **OCR 原文和 AI 摘要分开存放**，不能只留摘要。

### 笔记镜像到材料页

有关联资料的笔记，正文写在一个**同步块**里，材料页「我的想法」下追加这个同步块的引用。
两边改任意一处，另一处同步变化，正文只有一份。独立随想不包同步块。

`records` 里的 `body_parent_id` 记录正文实际在页面下还是同步块里；编辑 Telegram 消息时据此改写。
镜像失败只记日志，不影响笔记本身。

### 页面图标与缩略图

新材料按来源设平台 Logo 作页面图标，普通网页用站点 favicon，笔记按类型设图标。
缩略图优先内容封面 / 正文首图，论文和 PDF 优先完整插图、其次第一页，都没有时按九类内容
（论文、文章、教程、报告、帖子、图片、视频、音频、其他）选占位图。
HEIC/HEIF、ICO/SVG 只转换展示副本，原件照常归档。取图失败不影响正文保存。

## Firestore 数据模型

Notion 是阅读界面，Firestore 才是处理状态的 system of record。

| 集合 | 文档 id | 内容 |
|---|---|---|
| `updates` | Telegram `update_id` | 原始 update、状态、重试次数、回执消息 id |
| `records` | `{chat_id}:{message_id}` | 这条消息建出的 Notion 页面、类型、正文块 id、正文容器 id |
| `urls` | 归一化 URL 的 sha256 前 32 位 | 去重索引 → `records` 的 id |
| `pending_urls` | 同上 | 正在等 LLM 的链接，防止同一链接排两遍队 |
| `staged` | 同上 | 暂存区：链接、失败原因、尝试次数、附带想法 |
| `pending` | `{chat_id}` | 「记下想法」指定的材料，一小时过期 |
| `media_groups` | `{chat}:{group}` | 相册合并 |
| `image_jobs` / `video_jobs` | URL / 视频实体键 | 多图与视频任务的检查点和租约 |
| `settings` | `llm`、`tags` 等 | LLM 服务商、正式标签词表 |
| `ui` | `{chat_id}_{message_id}` | 按钮菜单的选项（callback_data 只有 64 字节） |

**Notion 和 Firestore 会漂移。** 在 Notion 删了页面，去重命中时会先确认页面还在，不在就重来；
反过来（Firestore 丢了、Notion 还在）会导致重复保存，目前不处理。
