# 标签

资料和笔记共用一个多选字段「主题」作为标签。不预建分类树，一条材料最多 3 个标签，可以留空。

## 词表从哪里来

- **初始种子**：`app/topics.py` 的 `GROUPS`。首次运行时写入 Firestore `settings/tags` 作为 v1，
  之后**以 Firestore 为准**，再改 `topics.py` 不会合并进已有词表。
- 仓库里自带的是一份通用的科技阅读示例（Agent、LLM、RL、Tool、Tutorial……共 24 个）。
  **部署前建议换成你自己的领域**，每个标签写一句「什么时候用、什么时候不用」的范围说明，
  模型按这个说明选标签，说明越具体越准。
- `_ALIASES` 把常见写法（中文名、缩写）归一到正式名；`_RETIRED` 里的名字永远不会被选中。

几条内置规则依赖具体标签名，删改这些标签时要一起改：

| 规则 | 位置 |
|---|---|
| `ML` 与 `LLM` 同时出现时都撤下，标记待确认 | `topics.audit()` |
| `MLSys` 与 `Systems` 不同时选 | `tag_store.normalize()` |
| 提示词中关于 ML / LLM / MLSys / Data / Dataset 的说明 | `topics.PRINCIPLES` |

## 自动打标

整理材料时，模型从当前启用的正式词表选 1–3 个标签，并为每个标签给出原文依据（`topic_evidence`）。
代码会检查：

- 只接受正式词表里的名字，模型不能自造标签；
- 每个标签的引文必须真的出现在来源里，否则撤下该标签；
- 拿不准时放进「待确认」建议，不直接写入。

Reply 产生的笔记在创建时继承关联资料的标签，之后不自动同步。

## 在 Telegram 里管理：`/tags`

| 操作 | 说明 |
|---|---|
| 查看 | 分页列出标签，点开看范围、别名、启用状态 |
| 新增 | 名称 + 一句范围说明；名称和别名跨标签唯一，大小写不敏感 |
| 编辑 | 改范围说明、别名；之后的整理使用新定义，已有材料不重标 |
| 停用 / 恢复 | 停用后不再推荐，历史标签保留 |
| 改名 / 合并 | 先预览影响的页面和视图，确认后由后台任务批量更新两个库，旧名变别名 |
| 改单条 | 回复一条已入库的 Telegram 消息发 `/tags`，勾选后只改这一页 |
| 纳管 | 在 Notion 里手工建的新选项，补一句范围说明后才会交给模型 |

所有操作先预览再确认，不调用 LLM。名称、说明等文字输入需要**手动回复**指定的提示消息，
没回复提示的普通消息仍按收集处理。

实现要点：

- 词表有版本号。改名 / 合并时新版本先存为「待同步」，两库同步完成后才发布给模型，避免并发导入写回旧名。
- 批量任务记录在 `tag_operations/{id}`，由 `/tasks/tags` 处理，失败可在 `/tags` 的「查看未完成任务」里重试。
- 批量任务只改「主题」字段，不动正文、阅读状态和其他属性。
- 同步视图筛选需要 Notion 新版 API（`2026-03-11`，仅这部分请求使用）；做不到时会列出需要手工收尾的视图。
  已知的标签快捷页可登记在 Firestore `settings/tag_navigation.pages`（`[{id, name}]`）。

测试：`tools/test_tag_management.py`、`tools/test_tag_classification.py`、`tools/test_topics.py`。
